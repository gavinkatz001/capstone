# Source assessment and preliminary training plan

The source list is [`docs/winter-2025/data-sources.txt`](../docs/winter-2025/data-sources.txt). I inspected the publishers' pages, the two GitHub repositories' file trees, local copies of the HR_IMU and Microchip files, and a UR Fall CSV. The first notebook deliberately trains on one **verified six-axis fall/ADL source**. Treating every link as interchangeable would hide missing channels, ambiguous units, different sensor placements, and missing subject IDs.

## Unified record contract

Each admitted source must produce a continuous recording with: `source`, source-prefixed `subject_id`, `recording_id`, `placement`, native sample rate, channel order, acceleration and gyroscope units, binary fall/ADL label, and optional fall type or event timestamps. The six numeric channels must become `[ax, ay, az, gx, gy, gz]` as `float32`, acceleration in **g**, gyroscope in **degrees/second**, uniformly sampled at **50 Hz**. Verify axis mapping from each dataset's documentation. Convert m/s² by dividing by 9.80665, rad/s by multiplying by 180/π, and downsample with an antialiasing resampler. Reject nonfinite values, unknown units, missing axes, and recordings too short for a window. Preserve source/placement metadata for evaluation.

## First training protocol

1. Split by **participant before windowing** so multiple trials or overlapping windows from one participant cannot cross train, validation, and test. Never treat Microchip trial numbers as proven participant IDs. A new source without participant IDs needs a trial-group split at minimum and should not be mixed into the primary subject-independent metric.
2. Use **4-second windows at 50 Hz** (200 × 6). HR_IMU falls are only about 16–22 seconds; padding to 60 seconds would make most of every sample artificial. In a fall recording, take one window centered on the strongest acceleration magnitude as a provisional event window. Leave the rest unlabeled. From each non-fall recording, take non-overlapping windows plus one window around its strongest motion as a hard negative. Event timing remains uncertain because the dataset provides recording labels, not impact timestamps.
3. Fit channel mean/std on training windows only. Use weighted sampling in training; choose a threshold on validation; score the held-out test subjects once. Report sensitivity, false-positive rate, AUC, confusion counts, split subject IDs, and recording-level metrics. These metrics describe **simulated wrist falls**, not clinical performance or 60-second packet false-alarm rates.
4. Save weights with the channel order, sample rate, units, normalization, threshold, and split metadata. For deployment on 60-second packets, run a 4-second rolling scan and **recalibrate packet-level** thresholds and false-positive rates. Avoid claiming that a window-level 10% FPR is a packet-level 10% FPR.

## Adding other sources later

After acquiring and inspecting FRDR or EdgeFall files, add a source-specific loader that returns the unified record contract and an explicit unit/axis mapping. Print per-source counts and sample ranges, then test on **held-out subjects and held-out sources**. If body placement or gravity removal differs, report performance by source/placement and consider separate models or calibration. Do not silently mix gravity-removed wrist acceleration with gravity-included neck/waist acceleration and assume they share a distribution.
